# 商品入库管理 技术方案

> 版本：v1.0（依据界面原型截图整理）
> 技术栈：Go 1.23 + Gin + GORM + MySQL（与《设计文档.md》保持一致）
> 关联文档：[设计文档.md](./设计文档.md)

---

## 1. 功能概述

商品入库管理对应后台侧边栏"商品入库"菜单（当前为 `javascript:void(0)` 占位），实现**商品信息录入 → 入库登记 → 商品列表 → 商品详情 → 编辑**的完整闭环。

**核心建模思想**：一台实物 = 一条商品记录，SN 码全局唯一。因此每条记录代表一台具体设备：

- 当前库存恒为 1（在库）或 0（已借出/不在库）
- 在库 / 已借出由状态字段表达，为后续"借用记录""样品异动"模块预留统计口径

### 1.1 页面清单（对应原型截图）

| 页面 | 路径 | 原型内容 |
|---|---|---|
| 商品列表页 | `/products` | 列表展示 + 商品入库 / 返回首页按钮 |
| 创建商品（入库登记）页 | `/products/add` | 商品信息 + 入库信息一张表单，按钮"确认入库 / 重置" |
| 商品详情页 | `/products/:id` | 基本信息 / 库存信息 / 其他信息 三段式 |
| 编辑商品页 | `/products/edit/:id` | 复用创建表单，SN 码等只读 |

### 2.3 商品详情页（三段式）

1. **基本信息**：商品名称、SPU、SKU、SN 码、分类、价格、样品归属人；右上角`编辑商品`按钮
2. **库存信息**：入库数量、当前库存、在库数量、已借出数量、所在仓库、所在仓位、库龄（天）

## 3. 关键设计

### 3.1 SN 码生成规则

格式：`SN + yyyyMMdd + 3 位当日序号`，例：`SN20240115001`。

- 渲染新增页时服务端预生成一个候选 SN 填入表单
- `生成 SN 码`按钮调用 `GET /products/api/sn` 换一个候选（JSON）
- 最终以**提交时服务端校验 + 数据库唯一索引**为准；写入时若唯一键冲突自动重取序号重试（最多 3 次）

序号获取：查询当日最大 SN（`sn LIKE 'SN20240115%'`）取尾号 +1，事务内完成，唯一索引兜底并发。

### 3.2 库存指标与库龄（不入库，查询时计算）

| 指标 | 计算规则 |
|---|---|
| 库龄（天） | `当前日期 − inbound_date`（Go 侧 `time.Since` 取天数） |
| 当前库存 / 在库数量 | `status == 1（在库）? quantity : 0` |
| 入库数量 | 入库登记时填写，默认 1，编辑可修正 |
| 已借出数量 | 当前迭代恒为 0；借用记录模块上线后由借用流水汇总 |

库龄、各项数量均**不落库**，详情页/列表实时计算，避免维护成本。

### 3.3 商品状态

`status INT`，**不设 gorm default 标签**（沿用状态字段约定，值由代码显式赋值）：

| 值 | 含义 |
|---|---|
| 1 | 在库（创建入库后默认） |
| 2 | 已借出（预留，借用模块使用） |
| 0 | 已出库/报废（预留） |

### 3.4 一级分类字典

固定字典常量（Go 内定义 + 模板渲染下拉），首版：`交通工具`、`电子设备`、`办公设备`、`其他`。二级分类为自由文本。若后续分类膨胀再升级为字典表。

### 3.5 移库

编辑时修改仓库/仓位即视为移库：仅更新 `warehouse_id / location_id` 两列，不动入库日期（库龄连续累计）。移库流水留给"样品异动"模块，首版不记录。

### 3.6 商品图片上传

- 保存目录：`static/uploads/products/yyyyMM/`，文件名重命名为 `sn.ext`（SN 唯一，天然防冲突、防路径穿越）
- 校验：后缀白名单 jpg/jpeg/png，大小 ≤ 5MB
- 模型存相对路径 `uploads/products/202609/SN20260920001.png`；编辑上传新图时删除旧文件

### 3.7 批量导入 / 导出

已确认为**不需要**，本期不实现。若后续需要，建议首版采用 CSV（标准库 `encoding/csv` 零依赖），需要 .xlsx 时再引入 `excelize`。

## 4. 数据库设计

新增商品表 `tbl_products`（建表 SQL 手动执行，见附录 A，不写入代码）：

|---|---|---|---|

| name | VARCHAR(100) | NOT NULL | 商品名称 |

| sku | VARCHAR(50) | | 可空 |
| spu | VARCHAR(50) | | 可空 |
| category | VARCHAR(50) | NOT NULL | 一级分类 |
| sub_category | VARCHAR(100) | | 二级分类（文本） |
| price | DECIMAL(10,2) | DEFAULT NULL | 价格（元） |
| owner_name | VARCHAR(50) | | 样品归属人 |
| warehouse_id | INT UNSIGNED | NOT NULL | 所在仓库（tbl_warehouses.id） |
| location_id | INT UNSIGNED | | 所在仓位（tbl_locations.id，可空） |
| inbound_date | DATE | NOT NULL | 入库日期（系统自动） |
| quantity | INT | NOT NULL DEFAULT 1 | 入库数量 |
| status | INT | NOT NULL | 1 在库 / 2 已借出（预留）/ 0 已出库（预留） |
| image | VARCHAR(255) | | 商品图片相对路径 |
| remark | VARCHAR(500) | | 备注 |
| created_by | INT UNSIGNED | | 创建人（tbl_users.id） |
| created_at / updated_at | DATETIME | | |
| deleted_at | DATETIME | | 软删除（建索引） |

**索引**：`uk_sn(sn)` 唯一；`idx_warehouse(warehouse_id)`、`idx_category(category)`、`idx_inbound_date(inbound_date)`、`idx_deleted_at(deleted_at)`。

## 5. 接口设计（全部挂 Auth 中间件）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /products | 商品列表（`page`、`keyword`、`category`） |
| GET | /products/add | 渲染创建/入库表单（预生成 SN，仓库/仓位下拉） |
| POST | /products/add | 提交入库（multipart/form-data 含图片），成功 → 详情页 |
| GET | /products/api/sn | 生成候选 SN（JSON `{"sn":"SN20260920001"}`） |
| GET | /products/:id | 商品详情 |
| GET | /products/edit/:id | 渲染编辑表单 |
| POST | /products/edit/:id | 提交编辑（multipart，支持换图/移库） |

## 6. 校验与异常处理

沿用现有"302 + `?error=` 提示"模式（与仓库/用户控制器一致）：

- 服务端校验：名称/一级分类/仓库必填；价格、日期格式校验；SN 唯一
- 创建走事务：写商品行，SN 冲突回滚重试
- 图片不合法：重定向回表单并提示具体原因，其余已填内容客户端保留
- 详情/编辑的 id 不存在：渲染 404 错误页（复用 `findWarehouse` 同款助手模式）

## 7. 安全设计

- 全部路由位于 `admin` 组，Auth 中间件保护
- 上传：后缀白名单 + 大小限制 + 以 SN 重命名（杜绝原始文件名路径穿越）
- 列表/详情均为登录内数据，无横向越权面（首版单角色 admin）

## 附录 A：建表 SQL（手动执行）

```sql
USE `sms`;

CREATE TABLE IF NOT EXISTS `tbl_products` (
  `id`           INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `name`         VARCHAR(100) NOT NULL COMMENT '商品名称',
  `sn`           VARCHAR(50)  NOT NULL COMMENT 'SN 码（自动生成，全局唯一）',
  `sku`          VARCHAR(50)  DEFAULT NULL,
  `spu`          VARCHAR(50)  DEFAULT NULL,
  `category`     VARCHAR(50)  NOT NULL COMMENT '一级分类',
  `sub_category` VARCHAR(100) DEFAULT NULL COMMENT '二级分类（文本）',
  `price`        DECIMAL(10,2) DEFAULT NULL COMMENT '价格（元）',
  `owner_name`   VARCHAR(50)  DEFAULT NULL COMMENT '样品归属人',
  `warehouse_id` INT UNSIGNED NOT NULL COMMENT '所在仓库',
  `location_id`  INT UNSIGNED DEFAULT NULL COMMENT '所在仓位',
  `inbound_date` DATE         NOT NULL COMMENT '入库日期（系统自动）',
  `quantity`     INT          NOT NULL DEFAULT 1 COMMENT '入库数量',
  `status`       INT          NOT NULL COMMENT '1 在库 / 2 已借出 / 0 已出库',
  `image`        VARCHAR(255) DEFAULT NULL COMMENT '商品图片路径',
  `remark`       VARCHAR(500) DEFAULT NULL,
  `created_by`   INT UNSIGNED DEFAULT NULL COMMENT '创建人',
  `created_at`   DATETIME     DEFAULT NULL,
  `updated_at`   DATETIME     DEFAULT NULL,
  `deleted_at`   DATETIME     DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_tbl_products_sn` (`sn`),
  KEY `idx_tbl_products_warehouse` (`warehouse_id`),
  KEY `idx_tbl_products_category` (`category`),
  KEY `idx_tbl_products_inbound_date` (`inbound_date`),
  KEY `idx_tbl_products_deleted_at` (`deleted_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品表（一台实物一条记录）';
```
