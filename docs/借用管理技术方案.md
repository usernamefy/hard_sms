> 技术栈：Go 1.23 + Gin + GORM + MySQL（与《设计文档.md》《商品入库管理技术方案.md》保持一致）
> 关联文档：[设计文档.md](./设计文档.md) · [商品入库管理技术方案.md](./商品入库管理技术方案.md)

## 1. 功能概述

借用管理对应侧边栏"借用记录"菜单与首页"快捷操作"中的**借用 / 归还**入口，实现**新建借用单（选商品 + 填借用数量）→ 借用列表 → 借用详情 → 归还**的完整闭环。

**与原型的差异（已确认的需求）**：

- **不做扫码功能**：原型中的"商品条形码 + 扫码枪扫描"流程整体去掉，改为在表单内**从在库商品下拉直接选择**商品加入借用清单
- **增加"借用数量"**：每条借用明细记录本次借用的数量，支持一张商品记录分多次部分借出/归还（商品表 `quantity` 为入库数量，可大于 1）

### 1.1 页面清单

| 页面 | 路径 | 内容 |
|---|---|---|
| 借用列表页 | `/borrows` | 筛选 + 列表 + 分页，`新建借用`按钮 |
| 新建借用页 | `/borrows/add` | 借用信息表单 + 商品清单（含借用数量），按钮"提交借用 / 重置" |
| 借用详情页 | `/borrows/:id` | 借用信息 + 商品明细（借用/归还数量），`整单归还`按钮 |

## 3. 关键设计

### 3.1 借用单号生成规则

格式：`BR + yyyyMMdd + 3 位当日序号`，例：`BR20260921001`。与商品 SN 生成完全同构：

- 渲染新增页时服务端预生成候选单号填入表单；`重新生成`按钮调用 `GET /borrows/api/no`（JSON）
- 提交时服务端以**当日最大单号 +1** 重新生成，数据库唯一索引兜底；唯一键冲突（1062）事务内重试，最多 3 次（复用 `models/product.go` 的 `nextSN`/`CreateProduct` 模式）

### 3.2 数量模型（核心口径）

商品表保持"一条记录 = 一批同物"的建模（`quantity` = 入库数量），**借用不写商品表的 `status`，全部由借用明细流水汇总**——这正是《商品入库管理技术方案》3.2 预留的口径（"已借出数量：借用记录模块上线后由借用流水汇总"）：

| 指标 | 计算规则 |
|---|---|
| 已借出数量(p) | `SUM(明细.借用数量 − 明细.已归还数量)`，关联借用单 `status=1`（借用中） |
| 可借数量(p) | `(p.status = 1 ? p.quantity : 0) − 已借出数量(p)`，下限 0 |
| 在库数量 / 当前库存(p) | `(p.status = 1 ? p.quantity : 0) − 已借出数量(p)` |

- 均为**查询时实时计算，不落库、不回写**，避免双向同步
- 商品 `status` 含义不变（1 在库 / 2 已借出 / 0 已出库），借用流程不修改它；"是否全部借出"由数量表达，首版不做状态自动流转（如需列表按"全部借出"筛选，再引入派生状态，见 9）

### 3.3 逾期

逾期不落库：列表/详情渲染时按 `借用单.status = 1 && 当前日期 > 预计归还时间` 计算，展示为红色"逾期"标签。

### 3.4 归还流程

- **首版支持整单归还**：`POST /borrows/return/:id`，事务内将该单所有明细 `已归还数量 = 借用数量`，借用单 `status = 2（已归还）`、`actual_return_date = NOW()`
- **部分归还**：表结构已预留（明细独立记录 `returned_quantity`），二期可加"按明细 + 数量归还"，无需改表

### 3.5 并发与事务

- 新建借用单：单个事务内完成——逐行 `SELECT ... FOR UPDATE` 锁定商品行 → 校验 `借用数量 ≤ 可借数量` → 插入主单 + 明细；任一行校验失败整体回滚并提示具体商品与可用量
- 借用单号：唯一索引 + 1062 冲突重试（同 3.1）
- 整单归还：事务 + 借用单行锁，重复归还幂等（已归还单直接提示"该单已归还"）

## 4. 数据库设计

新增两张表（建表 SQL 手动执行，见附录 A；本项目不使用 GORM AutoMigrate）：

**借用单主表 `tbl_borrow_orders`**

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT UNSIGNED | PK AUTO_INCREMENT | 主键 |
| borrow_no | VARCHAR(50) | NOT NULL UNIQUE | 借用单号，自动生成 |
| borrower_id | INT UNSIGNED | NOT NULL | 借用人（tbl_users.id） |
| borrower_name | VARCHAR(50) | NOT NULL | 借用人展示名（冗余，借用时快照） |
| department | VARCHAR(50) | | 借用人部门（选填） |
| borrow_date | DATETIME | NOT NULL | 借用时间（系统自动） |
| days | INT | NOT NULL | 借用天数（1~365） |
| expect_return_date | DATE | NOT NULL | 预计归还时间 = 借用时间 + 天数 |
| actual_return_date | DATETIME | | 实际归还时间，可空 |
| status | INT | NOT NULL | 1 借用中 / 2 已归还（0 预留已取消）；不加 gorm default，代码赋值 |
| remark | VARCHAR(500) | | 备注 |
| created_at / updated_at | DATETIME | | |
| deleted_at | DATETIME | | 软删除（建索引） |

**借用明细表 `tbl_borrow_items`**

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT UNSIGNED | PK AUTO_INCREMENT | 主键 |
| order_id | INT UNSIGNED | NOT NULL | 所属借用单（tbl_borrow_orders.id） |
| product_id | INT UNSIGNED | NOT NULL | 商品（tbl_products.id） |
| product_name | VARCHAR(100) | NOT NULL | 商品名称快照 |
| product_sn | VARCHAR(50) | NOT NULL | SN 快照 |
| quantity | INT | NOT NULL | **借用数量** |
| returned_quantity | INT | NOT NULL DEFAULT 0 | 已归还数量（整单归还得 = quantity） |
| created_at / updated_at | DATETIME | | |

**索引**：主表 `uk_borrow_no(borrow_no)` 唯一、`idx_borrower(borrower_id)`、`idx_status(status)`、`idx_deleted_at(deleted_at)`；明细 `idx_order(order_id)`、`idx_product(product_id)`（3.2 的汇总查询按 product 聚合走此索引）。

**GORM 模型**（`models/borrow.go`）：`BorrowOrder` / `BorrowItem` 结构体；商品数、借用数量合计、逾期标记、未归还数量等展示字段标 `gorm:"-"` 查询时填充。

## 5. 接口设计（全部挂 Auth 中间件，admin 组）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /borrows | 借用列表（`page`、`keyword`、`status`） |
| GET | /borrows/add | 渲染新建表单（预生成单号） |
| POST | /borrows/add | 提交借用单（`productIds[]` + `quantities[]` 数组字段），成功 → 详情页 |
| GET | /borrows/api/no | 生成候选借用单号（JSON `{"no":"BR20260921001"}`） |
| GET | /borrows/api/products | 商品搜索（JSON，`q` 按名称/SKU 模糊匹配在库商品，含可借数量与图片） |
| GET | /borrows/:id | 借用详情 |
| POST | /borrows/return/:id | 整单归还（表单按钮 + 确认） |

## 6. 校验与异常处理

沿用现有"302 + `?error=` 提示"模式：

- 服务端校验：借用天数 1~365；至少 1 行明细；每行数量 ≥ 1 且 ≤ 可借数量（同商品多行合并求和后校验）；商品必须存在且 `status=1`
- 可用量不足：提示具体商品名称与当前可借数量，表单已填内容保留
- 详情/归还的 id 不存在或已归还：渲染 404 错误页 / 重定向列表并提示（复用现有 `findXxx` 助手模式）
- 前端：借用数量 input 上限 = 选中行可借数量；预计归还时间随天数联动显示

## 7. 安全设计

- 全部路由位于 `admin` 组，Auth 中间件保护
- 借用人固定取当前会话用户（不信任表单传入的借用人 ID）
- 数量校验以服务端事务内锁行重验为准，前端限制仅为体验
- 首版单角色 admin，无横向越权面

## 9. 未决问题（不阻塞首版）

1. **借用人部门来源**：`tbl_users` 无部门字段，首版在借用单上手填选填；后续可在用户表加 `department` 并自动带出
2. **部分归还**：表结构已预留，二期按明细 + 数量归还
3. **逾期提醒**：仅做列表标签展示；站内/邮件提醒后续迭代
4. **商品"全部借出"派生状态**：如需在商品列表按全部借出筛选，再考虑回写 `status=2`（需同步处理归还后的状态恢复），首版不做

## 附录 A：建表 SQL（手动执行）

```sql
USE `sms`;

CREATE TABLE IF NOT EXISTS `tbl_borrow_orders` (
  `id`                 INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `borrow_no`          VARCHAR(50)  NOT NULL COMMENT '借用单号（自动生成，唯一）',
  `borrower_id`        INT UNSIGNED NOT NULL COMMENT '借用人，关联 tbl_users.id',
  `borrower_name`      VARCHAR(50)  NOT NULL COMMENT '借用人展示名（快照）',
  `department`         VARCHAR(50)  DEFAULT NULL COMMENT '借用人部门',
  `borrow_date`        DATETIME     NOT NULL COMMENT '借用时间（系统自动）',
  `days`               INT          NOT NULL COMMENT '借用天数（1~365）',
  `expect_return_date` DATE         NOT NULL COMMENT '预计归还时间 = 借用时间 + 天数',
  `actual_return_date` DATETIME     DEFAULT NULL COMMENT '实际归还时间',
  `status`             INT          NOT NULL COMMENT '1 借用中 / 2 已归还（0 预留已取消）',
  `remark`             VARCHAR(500) DEFAULT NULL,
  `created_at`         DATETIME     DEFAULT NULL,
  `updated_at`         DATETIME     DEFAULT NULL,
  `deleted_at`         DATETIME     DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_tbl_borrow_orders_no` (`borrow_no`),
  KEY `idx_tbl_borrow_orders_borrower` (`borrower_id`),
  KEY `idx_tbl_borrow_orders_status` (`status`),
  KEY `idx_tbl_borrow_orders_deleted_at` (`deleted_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='借用单主表';

CREATE TABLE IF NOT EXISTS `tbl_borrow_items` (
  `id`                INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `order_id`          INT UNSIGNED NOT NULL COMMENT '所属借用单，关联 tbl_borrow_orders.id',
  `product_id`        INT UNSIGNED NOT NULL COMMENT '商品，关联 tbl_products.id',
  `product_name`      VARCHAR(100) NOT NULL COMMENT '商品名称快照',
  `product_sn`        VARCHAR(50)  NOT NULL COMMENT 'SN 快照',
  `quantity`          INT          NOT NULL COMMENT '借用数量',
  `returned_quantity` INT          NOT NULL DEFAULT 0 COMMENT '已归还数量',
  `created_at`        DATETIME     DEFAULT NULL,
  `updated_at`        DATETIME     DEFAULT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_tbl_borrow_items_order` (`order_id`),
  KEY `idx_tbl_borrow_items_product` (`product_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='借用明细表';
```
